# Face Fraud Atlas 项目设计

本项目把综述论文的论证变成可查询、可解释、可维护的研究资源。用户不仅能够找到一篇论文，还能检查它的检测对象、证据前提、评测权限和向金融流程迁移的边界。项目配套匿名研究草稿，不以网站形式暗示已发表或已通过同行评审。

## 核心问题与组织框架

金融核验从媒体输入逐步走向身份、会话和业务权限。项目沿用四项证据要求：媒体真实性、身份一致性、采集与会话来源、有效业务授权。每项方法可以支持其中的一部分，却不能凭一个分数完成整个授权链。

攻击入口与媒体操作分别描述。呈现攻击和注入说明媒体如何进入核验路径；换脸、表情重演、生成、变形和识别规避说明媒体或身份证据如何被改变。相同伪造视频通过屏幕重放或采集后注入，会暴露不同的证据。因而目录、协议表单和解释文本不能把这些轴压成一个互斥列表。

项目初始数据为 141 篇研究文献、12 项官方资源、12 个基准和10幅研究图。153 是文献与官方资源的合计目录数；基准和图是另外两个集合。前端统计应由 JSON 生成，更新记录后不能继续显示过时的手工数字。

## 页面模块与读者任务

| 模块 | 读者的问题 | 交互和产物 | 解释原则 |
| --- | --- | --- | --- |
| 项目概览 | 这份综述连接了哪些问题？ | 四证据框架、研究状态、材料入口 | 匿名草稿状态可见；不虚构作者机构和发表结果 |
| 文献探索 | 哪些方法讨论同一问题？ | 搜索、主题/年份/发表形态筛选、条目详情、阅读清单导出 | 区分论文与官方资源，保留方法限制和来源 |
| 基准图谱 | 数据规模意味着什么？ | 单位分组、版本与模态卡片、协议和原始来源 | 不跨单位汇总或排名；未知不填零 |
| 风险分析 | 阈值错误和攻击基率如何影响决策？ | 基率/召回率/误告警率/会话数、预期告警组成 | 解析场景，不使用人脸模型推理，不给实际部署背书 |
| 协议构建 | 怎样组织评测设计的起点？ | 业务/入口/隔离因素选择与 JSON 导出，附阈值、分组和事件要求 | 导出的设计仍需补充实验细节；不代表已完成评测 |
| 图表与资料 | 论证依据和材料在哪里？ | 图预览、解释、数据/源下载 | 原论文统计、合成示意和解析曲线分别标记 |

建议的用户路径是“定义需要保护的判断 → 搜索方法 → 检查信息权限 → 核对基准 → 分析假设 → 导出协议与材料”。读者可以单独访问任何模块，无需完成强制步骤。手机界面应保持同样的内容语义，筛选与导出操作不依赖悬停。

## 视觉与可读性

首次进入使用英文与浅色主题。页面以研究名称、主题说明和论文、文献、代码入口组织首页；正向人脸示意与四项证据说明并列，图像明确标注为合成示意，不使用装饰性的检测分数。主色采用克制的蓝色，正文通常为16–18px，文献题名为20–22px，辅助文字保持足够对比度。内容留白与细分隔线承担主要层级作用。

科学插图采用宽幅预览并保持原比例，说明和材料入口与图分开排版。比较表允许区域内水平滚动，避免整页被宽表挤出手机屏幕。手机导航在两行内显示全部六个模块。英文说明单独维护于 `site/data/reading-notes.en.json`，忠实保留方法前提与金融证据范围。语言与主题控件在用户主动选择后记忆偏好。

## 数据与可维护性

开发输入、浏览器数据和研究下载分层保存：

```text
data/catalog-records.csv ───┐
data/benchmark-sources.csv ─┼─ scripts/build_catalog.py ─ site/data/*.json
paper-source/ ──────────────┘                           └ site/downloads/*.csv
Figure_Data/ ─────────── 编辑源、原数据、核验材料 ──────── site/downloads/Figure_Data.zip
site/assets/figures/ ─── 浏览器展示图
site/downloads/ ──────── PDF、LaTeX 项目、书目与资料压缩包
```

`site/data/catalog.json` 的顶层为 `papers` 数组，其中包含研究论文与官方资源；不能根据文件名把所有条目称作论文。`benchmarks.json` 保存基准；`taxonomy.json` 保存证据要求与场景；`stats.json` 保存生成的汇总。生成脚本输出这四个 JSON，并同步公开文献与基准目录 CSV；`assets.json` 与研究资料包在发布准备中另行更新。完整字段约定见 [DATA_SCHEMA.md](DATA_SCHEMA.md)。

维护时运行 `python scripts/build_catalog.py` 后，执行 `python scripts/validate_site.py` 检查本地资源、记录一致性和可编辑图源，再在 HTTP 服务中检查实际交互。GitHub Pages 工作流在生成后执行同一站点校验，不把初始版本的固定计数当作后续增补的限制。

记录 ID 与论文 BibTeX key 保持稳定。修正出版年份或页码不会改变一个方法的身份；已有预印本有正式版本时应先检查是否需要更新现有记录。研究结果不能从题目、标签或检索摘要自动补造。分类属于维护者的综述组织，不声称是原作者认可的官方分类。

书目核验、方法理解、金融相关性具有不同语义。当前目录用全局阅读范围说明和记录的金融证据层级保留这些差别，没有为所有记录声明统一的逐篇全文阅读状态。书目信息核验不代表全文统一深度阅读；金融迁移说明不代表已有银行业务实证。前端应把这些差别放在条目详情和项目说明中。

## 基准规模的解释

图表按原论文版本和单位分组展示规模，同时用模态矩阵显示观测渠道。它展示的是数据集合的组成，不是算法效果排行榜。视频、图像、人脸序列、同步多通道录制和通道流不构成同一个总体。

来源备注保留关键差异：OULU-NPU 的访问录像与注册录像分开；WMCA 使用论文定义的集合而非后来扩展网页计数；SiW 与 SiW-M 不同版本和原文计数矛盾需要明确；CASIA-SURF 和 CeFA 的通道流计数不能直接当作独立呈现次数。身份数也应说明是采集演员、基准身份还是更广泛源演员。未知字段显示“未核定”，不根据四舍五入的占比计算精确整数。

## 风险计算的科学边界

风险模块使用公开公式和用户输入。它没有检测模型，不接收真实人脸媒体，也不从图像生成攻击概率。计算结果是给定假设下的解析关系，而不是任何方法的实测性能。

阳性预测值随基率变化，需要明确“阳性”指所选任务的攻击或被标记事件。媒体操纵正类与金融工作流攻击正类不总是相同；真实录制的未经授权重用是典型例子。跨流程使用率必须说明其条件和分母。

当前交互计算器只显示预期混淆矩阵与告警精确率；重试、置信界和成本问题由研究正文和对应解析图讨论，不宣称已有这些交互功能。扩展时，重试公式需要独立、同分布且共同成功率的设定；真实自适应攻击可能改变概率和依赖结构。零错误的置信界使用独立伯努利试验假设，不能把同一人的相似帧当作同等独立样本。成本应使用最终互斥结果与各自代价，避免在多个中间环节重复计入同一错误。

## 协议 JSON 的用途

协议构建器产出一个可审阅的设计起点。当前可选择业务流程、攻击入口和身份/源媒体/生成器/设备/时间隔离因素；JSON 同时保留假设运行点、阈值验证、分组和事件要求。完整评测仍需实验者补充媒体操作、攻击者权限、参考样本信任、输入模态、训练/目标域数据权限、指标正类和分母、重试策略、合法用户可完成性，以及最终会话或业务结果。

JSON 可随实验仓库版本化，但网页导出本身不执行攻击、训练、测评或认证。不能预先填入虚构性能或将预设勾选标为“通过”。字段变动必须同步修改前端、schema、下载样例和说明。

## 图与下载的责任边界

十幅图分别配有解释与材料入口。原文核验的计数可用于描述性统计；风险曲线是解析场景；合成头像和流程图是示意。图注与网站说明需一致，不能把示意特征写成检测器输出，不能把解析曲线称为算法实测曲线。

完整 PDF、LaTeX 项目、书目和图表数据放在 `site/downloads/`。完整开发材料保留在仓库根 `Figure_Data/`；站点通过打包下载提供来源材料，避免不加区分地部署全部中间文件。论文中的书目排版去除 DOI/URL，核验链接另放目录和审计材料，以兼顾可读性与可追溯性。

## 交付与验收

发布前应完成本地数据生成、JSON 解析与 ID/数量一致性检查、页面实际加载、搜索/筛选/导出、基准备注、解析计算边界、协议下载、十幅图与各材料下载的核对；随后检查桌面与手机宽度、键盘操作、空结果和加载错误。Pages 部署成功后还须从最终公开 URL 检查路径与下载，不能仅凭工作流文件存在就宣布站点已上线。

维护中保留变更说明与源位置，允许无法判定的字段保持未知。项目代码使用 MIT；论文、研究汇编、图和第三方材料另行处理权利，不整体指定未知许可。
